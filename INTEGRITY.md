# INTEGRITY.md — sidecar annotations

This file is the **only** place an annotation about an immutable artifact is written.

Two classes of file in this repository are never edited after they land:

- **Archived memos** (`docs/from_core/`, `docs/to_core/` in the private repository —
  see the note below). Their `Integrity:` footers are digests over exact bytes; an edit
  invalidates the seal and destroys the record of what was actually sent or received.
- **Vendored copies** (`vendor/`). Frozen and never edited in place — a byte changed
  there is indistinguishable from tampering, which is the entire point of the digest
  pin (Core → Canary Response 001 §6).

When something in one of those files is *wrong*, the correction is recorded here as an
annotation against the file. The file itself does not move. An erratum that required
editing the artifact to record it would be an erratum that destroyed its own evidence.

---

## A note on the citations in this file

Entries below cite an internal correspondence channel by number — *Response 012 §2*,
*Note 008 §3*, and so on. **Those memos are not published in this repository.** They are
sealed, byte-frozen and archived where they were exchanged; what travels here is the
annotation, not the correspondence.

The citations are kept rather than stripped. An annotation whose provenance has been
quietly removed is weaker than one that names a source you cannot open: the first hides
that a source exists, the second tells you exactly what you are not being shown. Every
entry below states the defect, the file it is against, and the measurement that
establishes it — generated by the command that measured it, never transcribed. Those
stand on their own bytes. The citation says where the ruling was made, and nothing in an
entry depends on your being able to read it.

## R-C001 — vendored README states 20 self-test checks; v3 emits 38

**File:** `vendor/rederivable-manifest/README.md`
**Status:** acknowledged by core as core's own defect (Response 001 §6), owned.
**Action here:** annotation only. The vendored file is not edited.

The README's usage line reads:

>     python3 validate.py --selftest          # 20 checks: canonical form, seal/verify,

The count is stale: v2's 20 checks grew to 38 in the v3 hardening and the
prose did not move. Measured on this repository's vendored copy, with the gate's own
self-test:

```
$ python validate.py --selftest
... [PASS] lines counted: 38
ALL PASS
exit 0
```

**The root fix is core's, and removes the number rather than updating it.** A
hard-coded count is another number that rots — the same defect onedoor's README
carried with its test count. The self-test's contract is *"reports its checks, ALL
PASS, exit 0"*; the count belongs to the output, not to the prose. This repository
therefore asserts the contract and never the number: see
`tests/test_byte_discipline.py::test_vendored_selftest_contract`, which requires
`ALL PASS`, exit 0, and at least one check — and would not need changing if the count
moved again.

**The pin is intact.** Every file listed in `vendor/rederivable-manifest.SHA256`
recomputes to its pinned digest, 10 of 10 — so the stale sentence is
the upstream text as delivered, not a local modification.

## N-C001 — exit codes travel badly: `$?` after a pipeline is the pipeline's *last*
## command, not the gate

**Not a defect in any artifact.** Recorded here because it shapes CI, and because it
is the sharpest instance this session has produced of a gate that reports success
while attesting nothing.

**This entry was wrong when first written, and is corrected here.** The original text
said the Microsoft Store `python3` alias "prints an error and exits 0". The message is
real; **the exit code was not**. The forensics session audited the alias rather than
accepting its description and found it fails *loudly*; core carried the correction as
Forward 004a. The mechanism is one layer out from where I put it, and it is worse,
because it needs no Windows alias and no missing interpreter — it needs a pipe.

### The two measurements, beside the mechanism

| how the same command was measured | reported status | what it means |
|---|---|---|
| `python3 validate.py --selftest` — direct | **49** | the gate's true status. Recorded in the C0 assessment appendix, `EXIT=49` |
| `python3 validate.py --selftest 2>&1 \| tail -6` then `$?` | **0** | `tail`'s status. The gate's status was discarded by the pipe |
| the same pipeline, `${PIPESTATUS[0]}` | **49** | the gate's status, recovered |
| the same pipeline under `set -o pipefail` | **49** | the shell propagates the failure |

Measured directly, with a command whose failure is certain, so the mechanism holds
independently of any interpreter's state:

```
$ python -c "import sys; sys.exit(49)" 2>&1 | tail -2 ; echo $?
0
$ python -c "import sys; sys.exit(49)" 2>&1 | tail -2 >/dev/null ; echo ${PIPESTATUS[0]}
49
```

### How the error was made, since that is the reusable part

The false `0` was read off a **piped** invocation, while the correct `49` had already
been recorded — unpiped — in this session's own C0 appendix hours earlier. The defect
was not a missed measurement. It was a second, worse measurement contradicting a good
one already in the archive, and nobody, including its author, noticing the conflict.

### A note on reproducing it here today

**The shim behaviour is no longer reproducible on this host.** Re-measured on
2026-08-21 after Forward 004a, `python3` at the same path
(`AppData\Local\Microsoft\WindowsApps\python3`) now resolves to a working Python
3.12.10 and runs the self-test to `ALL PASS`, exit 0 — unpiped. The host changed
underneath the record. The `49` above therefore rests on two independent
measurements — this session's C0 appendix and the forensics session's audit — and not
on a measurement re-runnable today. Saying so is the point: a record that quietly
implied it had just been re-measured would repeat the original defect in a new form.

### The rule, canonical form (Forward 004a §2)

> **Exit codes travel badly** — through pipes, through wrappers, through `make`,
> through CI shells without `pipefail`. **The output contract is the only thing that
> travels with the work.** A verification claim quotes the gate's output against its
> contract; a bare exit status, or a description of success, attests nothing.

### Consequences — unchanged by the correction, and stronger under it

1. Gates in this repository are invoked as `python -m …` where a module entry point
   exists, and never through a name that may resolve to a shim.
2. No gate is trusted on exit code alone. Where a gate's contract includes output — as
   the self-test's does — the output is asserted against the contract.
3. Where a status must be taken from a pipeline, it is taken from `PIPESTATUS[0]` or
   under `set -o pipefail`, never from a bare `$?`.

Both original consequences survive the correction intact; the third is added by it.
All three are implemented in `.github/workflows/ci.yml` and in
`tests/test_byte_discipline.py`.

## N-C002 — README claimed zero live calls above a ledger reading 210

**File:** `README.md`, §"The live phase, and what governs it". **Corrected in place**
on 2026-08-27; this entry records what the file used to say, because the sentence was
launch-facing and was wrong for five days.

The line read:

> No live call has been made from this repository. When one is, four conditions bind it…

By then 210 live calls had been made — 150 in the C4 live run of 2026-08-22, 60 in the
two calibration runs — and the same README described that live run in detail forty lines
above. The C4-closing commit (`5695b09`) updated the findings sections and did not reach
the governance section beneath them.

**Why it is recorded here rather than only in git.** `README.md` is not an immutable
artifact, so the correction is a normal edit and the file did move. The entry exists
because the defect class is the one this repository exists to refuse: **an artifact
asserting something its own evidence contradicts.** A change-evidence tool whose front
page denies its own measurements is the failure mode, not a typo.

**Root fix owner:** canary build session. Self-caught during the Response 010 §2-A state
verification and self-reported as **F1** in Note 007 §2; core ruled it fixed immediately
(Response 011 §4, Q10 — "truth does not wait for a work order").

**How the correction was applied.** Under the substitution rule now standing
programme-wide (R052): the edit asserted its own effect — exactly one match before the
substitution, the false sentence absent and the replacement present after it, and a check
that the claim appeared nowhere else in the file. A mechanical edit that does not verify
what it did is a mechanical edit that reports success for having run.

## N-C003 — the three-outcome rule's standing example: 59 honest files called UNVERIFIABLE

**Recorded at core's instruction** (Core → Canary Response 012 §2): this is the standing
example of what the three-outcome rule buys, and it is kept here so the rule is never
argued about in the abstract again.

**What happened.** Re-deriving the C4 incident of record from a *deep* cold clone reported
**59 of 74 files UNVERIFIABLE**. Every one of those files was present and byte-correct.
The store addresses bodies as `runs/<64-hex>/bodies/<64-hex>` — 177 characters as
committed — and `Path.is_file()` answers `False` past MAX_PATH on Windows.
`canary/receipt/store.py` had carried the `\\?\\` fix for exactly this since it was
written, and had recorded why it refused the alternative — truncating a content address to
fit a filesystem trades the property the design rests on for a platform's convenience. The
checker had simply not adopted it.

**Why the vocabulary was the whole difference.** The checker said *unverifiable* — "could
not check". It did not say *failed* — "checked, and wrong". Those two words point at
different suspects: *unverifiable* points at the environment, *failed* points at the
evidence. Under a collapsed two-outcome vocabulary this would have read as **59 corrupted
files in the launch deliverable**, and the next hours would have gone to hunting tampering
in evidence that was never in doubt — a false accusation by a tool against its own
product, avoided by vocabulary alone.

**The two consequences, both now tested.**

1. *The coverage scan failed open.* Files invisible to `rglob` never entered the on-disk
   set, so an unpinned intruder at a long path went unreported. **A hole in the
   hole-finder fails in the direction of reassurance, which is the only direction this
   programme genuinely fears.** `test_the_coverage_scan_finds_a_file_whose_path_is_too_long`
   shows the scan a >260-character intruder and requires it to be found; the test was
   confirmed to fail against the `rglob` version and pass against the fix.
2. *The pin test carried the defect it was written to catch*, passing in the shallow
   working tree and failing only from the deep clone. Core's framing, adopted:
   **a gate is a command and the world it runs in; a green gate is a claim about an
   environment.** A verifier must be verified on the terrain it will verify on, and a
   Windows verifier's terrain includes MAX_PATH.

**Root fix owner:** canary build session. Self-caught by the cold-clone re-derivation
Response 011 §2 ordered, and self-reported as **F6** in Note 008 §3.

## N-C004 — co-occurrence in a document is not a statement (the F8 law)

**Recorded at core's instruction.** The most important defect this channel has caught, and
the reason is its *direction*.

**What it was.** The first `census()` in `canary/suite/corpus.py` matched the entity and
the attribute as **independent substrings**. Given a document holding

    The lattice shard uses a batch window of 31 milliseconds.
    The lattice relay uses a lease duration of 13 minutes.

it reported that the document answers *"what is the lease duration of the lattice shard?"*
It does not. Both terms are present; the statement is not.

**Why the direction is the whole point.** A census that was wrong the *other* way would
have excluded good packages — visible, annoying, harmless. This one could justify
**answerless arms against documents that genuinely lacked the fact**, and an answerless arm
over an answerable question scores a **correct** answer as an unsupported one.

That is a monitor **manufacturing an incident**. Every other defect on this channel spent
our confidence in our own artifacts; this one would have spent a customer's. For a product
whose entire pitch is that its alarms are evidence, **a manufactured incident is the one
failure worse than a missed one** — a missed change leaves the customer where they already
were, and a manufactured one sends them to tear apart a system that was working.

**The law, in the words it was found in: co-occurrence in a document is not a statement.**
Ground truth is computed from what the corpus *asserts*, never from which terms happen to
appear near each other. Generalised: a proxy that is *usually* equivalent to the property
you want will differ from it exactly where the stakes are highest, because that is where
the unusual cases live.

**What caught it.** A census audit of my own, before any live run, with both directions
tested — the crossed pairs required to return empty and the real pairs required to return
their document. Self-caught as **F8**, reported in Note 010 §4.

## N-C005 — the standing shape for every leak check on this channel

**Recorded at core's instruction** (Core → Canary acknowledgment of Note 010): the pair
below is the standing shape, and neither half is sufficient alone.

**Negative markers for the named secrets. Positive confinement for the unnamed ones.**

`SECRET_MARKERS` in `scripts/stage_disclosure.py` is a negative list: the seed's variable,
the credential's variable, the generator entry points. It works, and its limit is exact —
**a marker list can only catch what someone thought to name.** A negative list encodes
foresight, and foresight is precisely what is missing on the day something leaks.

`check_probe_text_confined()` needs none. It takes **what is actually secret** — the probe
text present in the published suite — and requires its absence everywhere else. It catches
the accident nobody named: a README quoting a probe to illustrate a point, a summary
pasting a corpus document, a debug dump nobody re-read before staging.

**And it refuses to pass on an empty search.** A confinement claim built from zero
fragments would be F6's failing-open shape in a new hat: a check that reports CLEAN because
it had nothing to look for, in the direction of reassurance, which is the only direction
this programme genuinely fears. See [N-C003](#n-c003) for the original.

## N-C006 — a name inside a published preimage is frozen the moment the first hash is published

**Ratified by core** on the close of the reopened channel, from the `v_digest` decision in
Note 011 §5.

**What happened.** Chaining instrument-health receipts needed a verdict digest for the
ledger row to commit to. The row's field is named `v_digest` — the *change* verdict — and a
health receipt carries `h_digest`. Renaming the field to something neutral would have been
tidier and obviously correct on its own terms.

**Why it was refused.** `Row.body()` is the **preimage** of `row_hash`. Rename a key in it
and every row already written hashes differently — including the three anchored rows of the
C4 incident of record, whose Merkle root `38ff95db…` is a published launch claim. The
change would have **silently moved a published root under the launch deliverable**.

That is exactly the class of quiet rewrite this product exists to make impossible, and it
would have been committed against ourselves, for aesthetics.

**The law:** *a name that lives inside a published preimage is frozen the moment the first
hash is published.* A tidier name is paid for with everyone's evidence. The field keeps its
name, its docstring says exactly what it holds, `verdict_digest_field()` records which
schema supplies which field, and an unknown schema is **refused rather than guessed** — a
ledger that chained a receipt shape it did not understand would commit to a structure
nobody had checked. `test_extending_the_ledger_did_not_move_the_incident_of_records_anchor`
asserts the root still recomputes.

**Riding with it:** a receipt with no `schema` raises a surfaced `LedgerError`, not a
`KeyError` from a dict lookup. **Malformed is a failure to surface, never a default case** —
a stack trace naming a missing key sends the reader hunting a bug in the ledger instead of
the malformed receipt in front of them.

## N-C007 — three phrases that joined the standing vocabulary

Ratified by core at the close of the reopened channel. Recorded together because each is a
decision rule, not a slogan, and each was earned by a specific defect.

**"The survivable direction."** F3's closure. `calibrate_c4.py` and `run_health_check`
write the run **before** computing the number, so a crash between acquisition and
measurement loses the number and keeps the evidence. Where an operation can fail partway,
choose the ordering whose failure mode is recoverable — and enforce it **by position rather
than by memory**, which is why a test asserts `put_run` precedes `counts()` in the source.

**"An instrument-health state is a report, not an alarm."** Saturation exits 0. A non-zero
exit teaches a scheduler to page someone on every scheduled run until somebody silences the
check — and **a silenced health check is worse than none, because it looks like one.**

**The asymmetry, kept verbatim as the F3 law's closing exhibit:** *the branch we cannot test
against real evidence is exactly the branch whose real evidence we threw away.* `SATURATED`
is tested against the recorded `gen-1-c4` baseline run; `DISCRIMINATING` has no recorded
example because F3 lost the only two non-saturated live runs this project ever had.
**Constructed fixtures labelled as constructed is the honest floor**, and the first budgeted
live calibration of the retrieval family will mint the real `DISCRIMINATING` example this
suite is owed.

## N-C008 — two laws from the viewer: structural fences, and guards that fail open

**Canonized by core** in Response 016 §1–§2, from the onewatch build.

### A fence enforced by imports holds while discipline sleeps

Constraint 4 required that every number on the page come from an engine function. The
enforceable form of *"never re-derive for display"* turned out not to be a rule at all:
`canary/viewer/page.py` imports no hashing module and cannot reach the engine — only
`canary.viewer.model`, which ran the verifiers. There is nothing in scope to re-derive
with, so the constraint cannot be violated by someone who has forgotten it.

**The law:** *a fence enforced by imports holds while discipline sleeps; a fence enforced
by discipline is a fence only while someone is watching.* **Where a fence can be
structural, make it structural.**

Others in this repository that already have this shape, and are worth recognising as the
same thing: `secure_c4_store.py` containing no delete path and asserting that about itself;
`calibrate_c4.py` having no `--switch-model` flag to forget to leave off; `health_check.py`
taking no model parameter at all. The pattern is always *remove the capability*, never
*document the prohibition*.

### A guard that fails open is worse than no guard

F9. `check_probe_text_confined` — the positive half of the leak check, built one session
earlier specifically to fix a blind spot — reported **CLEAN** over a page carrying a
verbatim ACTIVE probe. Two causes: it compared LF-bearing fragments against CRLF file text,
and deduplicated prefixes had collapsed thirty probes into the one preamble they share.

Core's ruling: this is not a weak check, it is an **anti-check** — it converts ignorance
into assurance.

**The law:** *a guard that fails open is worse than no guard: absent, it leaves you knowing
you have not looked; broken, it tells you that you have.*

It was caught by writing the sabotage core had asked for, which is the right-typed-lie law
(N-C006's neighbour) generalised: **only a test that plants a real leak proves the leak
check reads.** And the requirement stands that the sabotage must fail against the *old*
version before the fix counts as tested — it tests the defect, not the fix's presence.

### The E10 boundary, as recorded interpretation

Core affirmed the reading and made it the recorded one:

> **Evidence bytes: never normalised. Detector comparisons: normalised deliberately, and
> documented as such.**

E10 governs *evidence* — bytes that are hashed, compared for identity, or re-derived from.
A leak search produces no digest and no integrity verdict; it is a **detector**, and a
detector must be robust to its channel, because a leak that arrived with different line
endings is still a leak.

### Cross-channel note

The positive seal check's sabotage pair — a literal state word injected into the seal
region, plus the class-based route — is now the required test shape for onedoor's Studio v2
build. Core carries it there; nothing is owed from this channel. It is the first defect
found here that corrected another channel's test, which is the register working as
designed: nothing in it is authoritative because of who wrote it.

## How to add an entry

Give it an id (`R-` for an erratum against a received or vendored artifact, `N-` for a
note), name the exact file, state the defect, state who owns the root fix, and record
the measurement that establishes it — generated by the command that measured it, never
transcribed (X-11). Never edit the artifact.
